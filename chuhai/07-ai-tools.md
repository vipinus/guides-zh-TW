# 07 · 訪問 AI 工具（ChatGPT、Claude、Gemini 等）

## 現象

在國內開啟這些站點，症狀不太一樣，容易讓人誤判：

| 現象 | 多半是什麼 |
|---|---|
| 頁面完全打不開 | 網路層面到不了 |
| 頁面能開，登入時卡住 | 登入用的第三方服務到不了 |
| 能聊天，但一發長內容就斷 | 連線不穩定 |
| 提示 "not available in your country" | 服務商按 IP 拒絕 |
| 提示賬號被封或需要驗證 | 見下面"最重要的一條" |

## 最重要的一條：穩定比快更重要

這類服務對**IP 頻繁變化**特別敏感。如果你的連線一會兒從日本出去、一會兒從美國出去，服務商看到的是"同一個賬號在幾分鐘內跨了幾個國家"，很容易觸發風控——輕則要求重新驗證，重則封號。

所以用 AI 工具時：

- **選一個地區就固定用它**，不要頻繁切換
- 註冊和日常使用盡量在**同一個地區**
- 如果註冊時用的是美國，之後就一直用美國

這一條比"哪個地區更快"重要得多。速度差一點只是等待久一點，賬號出問題是要重新來過的。

## 選哪個地區

日本、新加坡離得近、延遲低，日常聊天體感最好。但有兩點要注意：

- 有的服務對某些地區的可用性不同，註冊前先確認那個地區能正常開啟
- 如果你要用的功能涉及支付，支付方式的歸屬地最好和你選的地區不矛盾

不確定的話，先用免費試用把要用的服務挨個開啟看一眼，再決定長期用哪個。

## 客戶端裡的"分應用"很有用

AI 工具通常在瀏覽器或者一個獨立 App 裡用。把它單獨放進走線路的名單，其餘 App 保持本地網路，好處是：

- 國內的外賣、打車、支付不受影響
- 你的地區不會因為別的 App 而"被動切換"
- 省流量

## 命令列和 API

如果你是透過命令列工具或者程式碼呼叫 API，注意那些程式**不一定讀系統代理**。這類情況見 [05 · Linux 與命令列](05-linux-server.md)。

## 一個提醒

不要在這些服務裡貼上公司機密、客戶資料、未公開的程式碼。這和用什麼線路無關——內容一旦發出去就在對方的伺服器上了。
